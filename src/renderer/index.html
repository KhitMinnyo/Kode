    🔌 AI Provider
    ⚡ Performance
    💡 Kode never exceeds your model's own context limit or this cap — raise it only if your model supports it and your machine has the RAM/VRAM to spare. Higher values use more memory per request.
    💡 How many model↔tool round-trips Kode will run before cutting a turn off with a "stopped after N steps" notice. Raise this if long multi-file tasks (or cloud models with longer useful runs) keep getting interrupted before finishing. Applies to all providers.
    🛡️ Safety
    💡 When the agent wants to run something risky (e.g. piping a downloaded script into a shell, decoding-and-executing base64), pause and ask you to approve or block it first instead of running it automatically. Recommended — turn off only if you fully trust the model and target.

    🖥️ LM Studio (Local)
    🔗 In LM Studio, open the Developer tab and Start Server, then load a model. Default is localhost:1234. To reach it over the LAN (Kali → Mac) just enter the machine's IP and port — e.g. 192.168.1.100:1234. The http:// and /v1 are added automatically if you leave them off.
    💡 Set this to match the context length of the model you loaded in LM Studio so long conversations get trimmed correctly.
    🧩 Custom / Other API
    🔗 Works with any OpenAI-compatible API — Groq, OpenRouter, Together AI, Mistral, Fireworks, xAI, Perplexity, or a local server (LM Studio, vLLM, llama.cpp server). Enter its base URL including the version path (usually ending in /v1). For a LAN server you can enter just an IP and port like 192.168.1.100:8000/v1 — the http:// is added automatically.
    💡 Kode can't auto-detect this provider's context limit — set it to match the model you'll use so conversations get trimmed correctly.
