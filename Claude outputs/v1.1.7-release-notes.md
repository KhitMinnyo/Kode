## Kode v1.1.7

### Security
- **Project file access is now scoped and authorized** — file and directory tools resolve paths against the selected project, including symlinks. Access outside the project requires user approval; unsafe paths fail closed.
- **Safer shell and network tools** — destructive shell commands go through explicit authorization, process cancellation also terminates child processes on Windows, and HTTP tools restrict protocols, enforce timeouts, and cap response sizes.
- **Persistent project state is kept out of project folders** — memory, embeddings, context summaries, plans, and saved full tool output now use Kode's per-user application data directory with restrictive file permissions. Existing legacy project memory remains readable.
- **Untrusted context is treated as context, not instructions** — earlier conversation summaries and saved plans are labeled accordingly to reduce the risk of instruction injection.
- **Renderer navigation is more tightly controlled** — only Kode's local application document is allowed to navigate in-app; redirects receive the same guard as ordinary navigation.

### Improved
- **More reliable Stop and process handling** — stopping a task can interrupt server startup and terminate its process tree; startup errors and early output are handled more consistently.
- **Bounded external responses** — external fetch responses are limited to 2 MB and HTTP tool responses to 1 MB, with cancellation and timeouts honored.
- **Persistent state follows the operating system's app-data conventions** — supports macOS, Windows, and Linux, with `KODE_DATA_DIR` available to override the storage location.

### Internal
- Added and expanded regression coverage for path authorization, state storage, cancellation, tools, and agent behavior.
- CI build workflows run the test suite and ESLint before packaging macOS, Windows, and Linux builds.
- Verified locally: `npm test` and `npm run lint` both pass.
